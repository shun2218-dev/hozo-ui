# レビューする

対象: $ARGUMENTS

## 手順

1. 対象ファイルを読む
2. **検証を実行する。推測で語らない**
   - `npm run typecheck`
   - `npm run test:types`（存在すれば）
   - 関連するテスト
3. 意図した型になっているか確認する
   - 必要なら一時ファイルで `expectTypeOf` / `@ts-expect-error` を書いて確かめる
   - 一時ファイルは `/tmp` に置き、リポジトリを汚さない
4. `CONCEPT.md` の設計原則 1〜6 に照らす
5. 結果を報告する

## 報告の形

```
## 検証結果
tsc: <pass/fail>
型テスト: <pass/fail>

## 指摘
1. <問題の所在。直し方は書かない>
2. ...

## 原則との突き合わせ
原則 N: <該当あれば>

## 良い点
<あれば理由込みで。なければ書かない>
```

## 厳守

- 修正版のコードを書かない。「ここが問題です、どう直しますか」で止める
- `src/` を編集しない
- ついでに直さない
- エラーメッセージが読みにくい場合、それ自体を指摘対象にする（原則 3）
- 型が過剰なら削るよう促す（原則 6）
