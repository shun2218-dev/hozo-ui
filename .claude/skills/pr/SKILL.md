# PR をレビューして本文を作る

マージ先: $ARGUMENTS（省略時は `develop`）

`/review` が「書いたコード 1 箇所」を見るのに対し、これは**ブランチ全体**を見る。

## 手順

### 1. 範囲を確定する

```bash
git log --oneline <マージ先>..HEAD
git diff <マージ先>...HEAD --stat
```

コミットが 0 件なら、そこで止めて報告する。

### 2. 検証を実行する。推測で語らない

```bash
npm run typecheck && npm run test && npm run test:types && npm run lint
```

**1 つでも赤ければ、その時点で報告して止める。** 赤いまま PR 本文を作らない。

### 3. 差分を読む

```bash
git diff <マージ先>...HEAD
```

`src/` の変更は必ず全部読む。設定ファイルとドキュメントは変更点だけでよい。

### 4. テンプレートを読む

**`.github/PULL_REQUEST_TEMPLATE.md` を読み、その節構成に従う。** ここに節を書き写さない。テンプレートが変わったら自動的に追従させるため。

### 5. 埋められる欄と、埋められない欄を分ける

**Claude が埋める欄** — 差分と検証結果から機械的に決まるもの。

- 何をしたか（差分の要約）
- 検証のチェックボックス（実際に走らせた結果のみ。走らせていないものにチェックを入れない）
- 公開 API への影響（下記 6 の調査結果）
- 記録のチェックボックス（下記 7 の調査結果）

**本人が埋める欄** — 判断や意図を含むもの。空欄のまま渡し、「ここは自分で書いてください」と明示する。

- **なぜそうしたか**
- **原則との突き合わせ**（該当する原則の見当は示してよいが、チェックは入れない）
- **テストが効いていることの確認**（変異テストを実際に回したかは本人しか知らない。Claude が代わりに回した場合は、何をどう壊して赤くなったかを事実として書く）
- 積み残し

### 6. 公開 API の変更を洗い出す

差分から次を機械的に拾う。

- `src/index.ts` の export の増減
- `hozo-` で始まるクラス名の追加・変更・削除
- `data-` で始まる属性の追加・変更・削除

いずれも `LEARNING_LOG.md` の D-006 で公開 API と定めたもの。**変更があれば破壊的変更の候補として明示する。**

### 7. 記録漏れを調べる

- `src/` に変更があるのに `LEARNING_LOG.md` が変わっていない → 学習記録または設計判断が要るか確認を促す
- 型定義（`*.types.ts` / `src/types/`）が変わっているのに `docs/error-messages/` が変わっていない → エラーメッセージの再採取が要るか確認を促す

**「要る」と決めつけない。** 設定変更やリファクタなら不要なこともある。

### 8. 報告する

まず所見、次に PR 本文の下書き。

## 報告の形

````
## 検証結果
typecheck:  <pass/fail>
test:       <pass/fail>（N tests）
test:types: <pass/fail>（N tests）
lint:       <pass/fail>

## 差分の範囲
<コミット数とファイル数。主要な変更を 3 行以内で>

## 指摘
<マージ前に直すべきもの。無ければ「なし」>

## 公開 API の変更
<型 / クラス名 / data-* の増減。無ければ「なし」>

## 記録の状態
<LEARNING_LOG.md と docs/ の更新有無。漏れの疑いがあれば指摘>

---

## PR 本文の下書き

```markdown
<テンプレートの節構成に従った本文。本人が埋める欄は
<!-- ここは自分で書く --> を残す>
```
````

## 厳守

- **確認していないことを「確認済み」と書かない。** 実行した検証だけをチェックする
- **「なぜそうしたか」を代筆しない。** 差分から読み取れるのは「何をしたか」までで、判断の理由は本人しか知らない
- 原則との突き合わせは、**該当しそうな原則を挙げるところまで**。チェックは本人が入れる
- 修正版のコードを書かない。`/review` と同じく問題の所在だけ示す
- `src/` を編集しない
- **PR を作成しない。** `gh pr create` を実行しない。本文を渡すところまでが仕事で、出すかどうかは本人が決める
- テンプレートの節を勝手に増減しない。テンプレート自体を変えたいときは、その旨を別途提案する
